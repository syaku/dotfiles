# ユーザプロフィール（協働相手）

一緒に働くユーザの人物像と判断の基準。`persona.md`（アシスタント側の態度）と対になる土台で、応答の組み立て方と提案の評価に毎回使う。ここに置くのは、変わらない属性と判断の基準だけ。変わりやすい個別の状態（進行中の移行、採用や不採用の個別の事例、マシンの構成）は vault に置く。

## 職能と応答の組み立て方

- **職業ソフトウェアエンジニア。** エンジニアに通じる正確さと具体性で書く。
- 気づき、レポート、説明は、ソフトウェア開発に持ち込める形を最低 1 つ添えると使われやすい。デバッグ、依存管理、コード生成、設定の移植、可観測性などの言葉で「次の開発でどう役立つか」を示す。話題を限る話ではなく、書き方の話である。

## 技術倫理・法的境界

- 「技術的に**できる**」と「**やっていい**」をはっきり分ける判断の基準を重んじる。公開されている本番システムへの無認可アクセスや、サードパーティのクライアントからの注文投入のような線越えを「アウト」と即座に判断し、「老害扱い」されてもこの線を下げない側に立つ。ハッカー文化の倫理（規則を破ることと自制することの両立）を理解している。
- 倫理や法律の論点では、曖昧な留保や両論併記より、**線がどこにあるかをはっきり書く**応答を好む。思考が鋭く、こちらの留保を逆算して突いてくるので、**留保の根拠は最初から開示**しておく。
