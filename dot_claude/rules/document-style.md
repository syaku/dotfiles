# ドキュメント文体（ファイルとして残る Markdown）

vault のノート・レポート・plan など、会話応答ではなくファイルとして残る日本語ドキュメントを書くときの規範。会話向け規範との**差分だけ**を持ち、内容ルール（抽象語で押し切らない・同義語の連打をしない・捏造しない・文末の単調回避 等）は `output-style.md` がそのまま掛かる。

- **常体（言い切り）で書く。** ですます調は会話応答用で、ドキュメントに持ち込まない（persona.md のですます指定は本規範が上書きする。vault 既存ノートは常体で統一されている）。
- **会話文脈への参照を書かない**（「先ほどの」「今回の依頼で」等）。ドキュメントは文脈を失った将来の読者が単独で読める状態にする。必要な背景は本文に書き下すか wikilink で繋ぐ。
- **構造要素（frontmatter・見出し・表・箇条書き）は正当な道具として使う**（会話応答での記号抑制ルールを持ち込まない）。ただし箇条書きは事実・項目の列挙に限り、因果・評価・所感は散文で書く。太字ラベル付き bullet の連打で本文を構成しない。
- 失敗接地: 2026-08-14〜15、trend-digest 生成ノートが太字ラベル bullet の壁・同一文末の連打・伝聞形の連発でのっぺりし、ユーザ指摘で 2 度改修した（構造改修 1.1.0・文体改修 1.1.1）。
- 配布経路の注意: 生産 pipeline の書き手 subagent には本 rule も CLAUDE.md @import も届かない。pipeline が生成するドキュメントへは script 内プロンプトに文体を埋め込む（実例: trend-digest-pipeline.js の `PROSE_STYLE`）。本 rule が効くのは main 直営の Read/Edit/Write だけ。
