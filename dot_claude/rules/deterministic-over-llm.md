# 結果が一つに決まる処理はコードに書き、決まらない判断だけを LLM に残す

スキル、workflow、agent を組むとき、**結果が一つに決まる処理を LLM の prompt に任せない。** 件数を数える、モードで分岐する、lint、証拠の突き合わせ、書式の強制、しきい値の判定はコードで実装する。LLM に残すのは、正解が一つに決まらない判断（命名、洞察を見つけること、意味の解釈、設計の取捨）だけにする。

- 判定: 迷ったら **「LLM が嘘をついても script が見つけられる形か」** を問う。見つけられないなら、決まる処理を LLM に渡している。
- 逆向き: 判断が一つに決まらなくても、**判断を始める合図はコードの側に置ける**。hook の `type: "prompt"` / `"agent"` は必ず動き、判断だけを LLM がする。ただし判断の中身は LLM 自身の申告と同じ弱さを持つので、機械の判定の置き換えではなく、その上に足す形で使う。
- 元になった失敗: prompt に置いた件数の集計、命名の検査、モードの固定が、LLM 自身の申告に頼っていたためにずれていき、harvest-pipeline / plan-pipeline でコードへ移した（2026-06-13）。
